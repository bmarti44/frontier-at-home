### HIGH

1. **The cgroup ceiling does not bound GPU memory on this host.** [run_smoke.sh:53](/home/bmarti44/spark-deepseek-v4-flash/results/dsv41-flash-gates/harness/run_smoke.sh:53) sets `MemoryMax=76G`, but the [failed attempt record:19](/home/bmarti44/spark-deepseek-v4-flash/results/dsv41-flash-gates/smoke-2026-09-25/text-attempt2-FAIL/failure.json:19) reports a 1.2 GB cgroup peak while `MemAvailable` fell by about 63 GiB. Thus the [preregistered “physical memory minus MemoryMax” calculation:38](/home/bmarti44/spark-deepseek-v4-flash/results/dsv41-flash-gates/smoke-2026-09-25/PREREGISTRATION.md:38) is not a safety bound for CUDA allocations. At 1M context, additional allocations could exhaust UMA before the periodic 40 GiB sampler reacts. **Fix:** size cache and context from measured whole-system peaks, retain the external kill floor and cgroup controls, and validate a separate production floor before a direct 1M run.

2. **The runner does not enforce the frozen binary or continuous process identity.** [run_smoke.sh:53](/home/bmarti44/spark-deepseek-v4-flash/results/dsv41-flash-gates/harness/run_smoke.sh:53) does not enable `GLM_SAFE_LOG_CANDIDATE_PROVENANCE` or pass an expected binary hash. The [wrapper defaults that check off:27](/home/bmarti44/spark-deepseek-v4-flash/results/glm52-gates/harness/glm_safe_run.sh:27), and its [continuous identity checks are conditional on it:437](/home/bmarti44/spark-deepseek-v4-flash/results/glm52-gates/harness/glm_safe_run.sh:437). A binary replaced after the freeze could run under the pinned pathname and produce apparently comparable output. The currently readable `ds4` and `score_official` hashes do match `frozen-inputs.json`; that does not prove the executed binaries did. **Fix:** make the wrapper verify each arm’s exact executable hash, PID/start time, and executable identity throughout the run, including `score_official`.

3. **Malformed paired TSVs can receive PASS.** [score_fidelity.py:26](/home/bmarti44/spark-deepseek-v4-flash/results/dsv41-flash-gates/harness/score_fidelity.py:26) checks finite values and duplicate IDs, but [lines 53–56](/home/bmarti44/spark-deepseek-v4-flash/results/dsv41-flash-gates/harness/score_fidelity.py:53) accept any shared set of 112 IDs. They do not require the frozen fixture’s IDs, positive integral token counts, equal API coverage, or `0 ≤ api_top1_match ≤ api_top1_count`. For example, invented IDs in both arms and negative CUDA NLLs can satisfy both upper bounds. **Fix:** validate IDs against the hashed manifest, field ranges and integer types, per-case coverage, and both arms before bootstrap; add mutations for these cases.

4. **The GGUF parser cannot reproduce the roofline tensor sizes.** For arrays longer than 64, [gguf_tensor_sizes.py:9](/home/bmarti44/spark-deepseek-v4-flash/results/dsv41-flash-gates/harness/gguf_tensor_sizes.py:9) returns without consuming their payload. A bounded header read found a 129,280-element metadata array before tensor descriptors, so subsequent parsing starts at the wrong byte. The script also reads but does not validate magic or version at [line 13](/home/bmarti44/spark-deepseek-v4-flash/results/dsv41-flash-gates/harness/gguf_tensor_sizes.py:13). **Fix:** correctly skip every GGUF value type, validate v3/header bounds and offsets, and regenerate the result. An independent header-only read *did* reproduce the reported routed and Engram byte totals; the numbers are plausible, but this committed script cannot establish them.
